# UX audit — HSPA Monitor (hspa-cesko.cz / skorezdravotnictvi.cz)

**Datum:** 2026-06-11 · **Rozsah:** všechny hlavní stránky (desktop 1440 px + mobil 390 px),
CSS/JS code review, axe-core a11y scan, měření váhy stránky.

**Metodika:** lokální server (`npm run serve`) + headless Chromium; screenshoty
homepage po sekcích, fold + full-page u 16 stránek, mobilní varianty, dark-mode
emulace, test vyhledávání (`/`), axe-core na 4 stránkách, inspekce
`src/styles.css`, `src/app.js`, `src/indicator.js`, `src/kraje.js`,
`src/newsletter-popup.js`. Pozn.: sandbox blokuje externí CDN — což shodou
okolností odhalilo nejzávažnější nález (§1).

---

## Co funguje výborně (nerozbíjet)

- **Editorial vizuální jazyk** — papírová estetika, serif/sans hierarchie,
  červená jen jako akcent, brand kompas. Působí důvěryhodně a odlišně od
  typických „dashboardů".
- **404 stránka** — vzorová: vysvětlení, 3 CTA, rozcestník hlavních sekcí.
- **Vyhledávací overlay** (`/`) — seskupené výsledky (Články / Indikátory /
  Glosář) se zvýrazněním shody, rychlá odezva.
- **A11y základ** — axe-core téměř čistý (jen 2 moderate nálezy, viz §15),
  `aria-expanded` na mobilním menu, skip-link, komentované WCAG 2.5.8 target
  sizes v CSS, `prefers-contrast: more`, 10+ bloků `prefers-reduced-motion`.
- **Transparentnost AI autorství** — banner „Tento článek nepíše člověk" je
  upřímný, vtipný a má odkaz na vysvětlení i hlášení chyb.
- **Newsletter popup má frequency capping** (30 dní po zavření, nikdy po
  přihlášení) — vzácně dobrá praxe; zbývající problémy viz §5.
- **Cesta pacienta, strategie, tematické linie** — silné narativní stránky,
  čísla v pravém sloupci dávají okamžitý kontext.

## A. Kritické nálezy (vysoká priorita)

### 1. CDN je single point of failure — detail indikátoru a krajská mapa umřou celé

Když se nenačte CDN knihovna (firemní proxy, výpadek jsdelivr/cdnjs, offline,
adblock):

- **`indicator.html` spadne kompletně.** `renderTrendChart()` →
  `new Chart(...)` vyhodí `ReferenceError`, vnější `try/catch` v `init()`
  (`src/indicator.js:61`) nahradí **celou stránku** hláškou „Nepodařilo se
  načíst data: Chart is not defined." Přitom data jsou lokální JSON a načetla
  se v pořádku — uživatel nevidí hodnotu, benchmark, metodickou kartu, nic.
- **`kraje.html`**: mapa zobrazí chybu („Knihovna echarts se nepodařilo
  načíst"), ale **žebříček krajů zůstane prázdný**, ačkoli tabulka knihovnu
  nepotřebuje.
- **Homepage**: regionální mapa a finanční donut zůstanou prázdné bílé boxy
  bez jakékoli hlášky (regionální *tabulka* naštěstí funguje).

**Doporučení (v pořadí dopadu):**
1. Graceful degradation: graf renderovat až po `typeof Chart !== 'undefined'`
   guardu; když chybí, vykreslit trend jako SVG sparkline nebo tabulku roků —
   `article-visuals.js` už SVG bez závislostí umí, stejný přístup použít zde.
   Zbytek detailu indikátoru se musí vykreslit vždy.
2. Self-host knihoven (`assets/vendor/chart.umd.js`, echarts) — web je jinak
   plně soběstačný (žádné API klíče, lokální data), CDN je jediná externí
   runtime závislost. Self-host zároveň zlepší soukromí (žádný request třetí
   straně) a CSP.
3. Chybové hlášky říkat pravdu: „Graf se nepodařilo vykreslit, hodnoty níže
   platí" ≠ „Nepodařilo se načíst data".

### 2. Rozbitý odkaz „PROHLÉDNOUT139INDIKÁTORŮ" na homepage

`.ed-narrative-links a` má `display: inline-flex` (`src/styles.css:4168`),
takže text node + `<span data-stat>` + text node se stanou flex items a
mezery mezi nimi zmizí → „Prohlédnout139indikátorů". Fix: buď `gap: 0.3em`
na odkazu, nebo `display: inline-block` + zarovnání šipky jinak, nebo obalit
celý text do jednoho spanu.

### 3. Nekonzistentní počty indikátorů na jedné obrazovce

Vedle sebe se uživateli ukazuje: „**139** indikátorů" (nadpis sekce, odkaz
04), „**136** CELKEM" (scorecard pás) a v meta description / statickém HTML
fallbacku „**80** indikátorů". Příčina: `scTotal` počítá `visible.length`
(po filtrech), nadpis počítá vše, HTML fallbacky jsou zastaralé.

**Doporučení:** jeden zdroj pravdy (`stats` objekt z `indicators.json`),
scorecard explicitně označit „zobrazeno po filtru: 136 / 139", HTML fallback
hodnoty generovat ze skutečných dat (build krok nebo test, který je hlídá —
test na shodu `data-stat` fallbacků s `indicators.json` by zachytil i meta
description).

### 4. Čísla nejsou formátovaná česky

Karty indikátorů renderují `${ind.value}` přímo (`src/app.js:578`):
„**17989.8** na 100 000 ob.", „**803252** od / rok", „**2.736 %**" — zatímco
finanční sekce o pár obrazovek níž správně píše „55,3 %", „244,5 mld Kč".
Desetinná tečka vs. čárka na jedné stránce. Navíc jednotka „od / rok"
(ošetřovací dny?) je nesrozumitelná zkratka.

**Doporučení:** jednotná formátovací funkce
`formatValue(n) → toLocaleString('cs-CZ')` (mezera jako oddělovač tisíců,
čárka desetinná) pro karty, benchmark popisky i trend %. Jednotky psát
lidsky („ošetřovacích dnů/rok"). `toLocaleString('cs-CZ')` už v
`src/app.js:303` existuje — jen ho používat všude.

### 5. Newsletter popup překáží

Popup (pravý dolní roh) po doscrollování 55 %:

- **Překrývá obsah karet** — zdroje a „Detail →" odkazy posledního sloupce
  gridu jsou pod ním nečitelné/neklikatelné, dokud ho uživatel nezavře.
- **Koliduje se scroll-to-top tlačítkem** (oba pravý dolní roh).
- **Duplikuje footer** — když uživatel doscrolluje k patičce, vidí dva
  identické newsletter formuláře přes sebe (popup + footer blok).
- Zobrazuje se na **každé stránce znovu**, dokud ho uživatel aktivně nezavře
  (capping platí jen pro zavření/přihlášení, ne pro zobrazení).

**Doporučení:** (a) skrýt popup, jakmile je footer newsletter ve viewportu
(IntersectionObserver na `.newsletter-block`); (b) session cap — max 1
zobrazení za návštěvu (`sessionStorage`); (c) posunout popup nad scroll-top
tlačítko nebo scroll-top schovat, dokud je popup otevřený; (d) zvážit trigger
až po 2.–3. zobrazené stránce (první návštěva = poznávání webu, ne konverze).

## B. Přehlednost informací

### 6. Homepage je ~19 400 px dlouhá a renderuje všech 139 karet najednou

Skvělý obsah, ale orientace trpí: mezi hero a patičkou je 7 velkých sekcí
a stěna 139 karet. Uživatel nemá náhled, kde v té délce je.

**Doporučení:**
- Progressive disclosure gridu: zobrazit prvních ~18–24 karet (prioritně
  kritické + ověřené) a tlačítko „Zobrazit všech 139" — sníží i DOM
  (aktuálně 4 300 nodes) a initial render.
- Sticky mini-navigace sekcí homepage (Přehled · Dimenze · Indikátory ·
  Kraje · Finance) — jednořádková, objeví se po opuštění hero. Návštěvník
  získá mapu stránky a rychlé skoky.
- Alternativně grid defaultně sbalit po doménách (akordeon s počty), jak to
  dělá hspa-prehled.

### 7. Karty indikátorů — drobnosti, které sčítají šum

- **Interní ID místo jmen zdrojů**: „Zdroj: share", „Zdroj: nrc",
  „Zdroj: sukl_atc", „Zdroj: mzcr_ehealth", „Zdroj: uzis_nrpzs" vs. správné
  „Zdroj: ÚZIS · NZIS". Mapping tabulka ID → lidský název (+ test, že žádný
  `source.name` neobsahuje podtržítko).
- **„Detail →" se láme na dva řádky** u karet s dlouhým textem zdroje —
  `white-space: nowrap` na odkaz.
- **Karty bez benchmarku zejí prázdnotou** (např. Incidence hepatitidy,
  Kolorektální karcinom) — velká bílá plocha mezi hodnotou a zdrojem.
  Využít ji: mini-sparkline trendu (data v `indicators.json` už jsou!),
  nebo aspoň poslední 3 roky textově. Sparkline by kartám dodal i pohyb
  a důvod kliknout na detail.
- **Extrémní trend „↑ 2631.5 %"** (černý kašel) působí jako bug. U změn
  nad ~200 % přepnout na násobky („27× více než loni") nebo absolutní
  vyjádření; přidat title/tooltip s oběma hodnotami.

### 8. Finanční sekce: 459 vs. 422 mld Kč bez vysvětlení vztahu

Nadpis sekce říká „Úhrady 7 zdravotních pojišťoven · 2023 · **459 mld Kč**",
donut o kus níž „**422** MLD KČ 2023". Obě čísla jsou nejspíš správně (jiný
záběr), ale čtenář vztah nezná. Jedna věta pod donutem („422 mld = úhrady za
zdravotní služby; zbývajících 37 mld = …") to vyřeší.

### 9. Glosář — české řazení abecedy

Abecední lišta řadí „3, A…W, Z, **Ú, Č, Š, Ž**" — diakritika je vyhozena na
konec (ASCII řazení). České řazení = Č za C, Š za S atd. Použít
`Intl.Collator('cs')` pro řazení skupin i termínů. Při 199 termínech by
pomohla i sticky abeceda lišta při scrollu.

### 10. Drobné textové/UI nálezy

- Meta description homepage tvrdí „80 indikátorů" — zastaralé (viz §3).
- `indicator.html` má nahoře „← zpět na přehled indikátorů" a breadcrumb
  v brandu — duplicitní navigace, stačí jedna.
- Hero stat karty (80,1 let / 7,7 let / 463,8 / 4,2) používají správně
  čárku — o to víc bije do očí tečka v gridu (§4).

## C. Animace

**Stávající stav je solidní:** brandNeedleSettle (kompas se „ustálí na
sever" — pěkný brand moment), count-up scorecardu, IntersectionObserver
reveal, 116 transitions/keyframes, vše respektuje `prefers-reduced-motion`.

**Návrhy na rozšíření (vše krátké 200–400 ms, za reduced-motion guard):**

1. **Benchmark bary na kartách animovat při vstupu do viewportu** (fill
   zleva, stagger ČR → OECD → EU ~80 ms) — dnes statické; animace by
   zdůraznila porovnání, což je jádro sdělení karty.
2. **Count-up pro `big-value` na kartách** při prvním zobrazení — systém
   `setCounterEl` už existuje, stačí ho navěsit; sjednotí pocit s heroes.
3. **Skeleton loading** místo prázdných boxů během fetch JSON (grid,
   žebříček krajů, donut) — vnímaná rychlost; dnes obsah „naskočí".
4. **Scroll-spy zvýraznění TOC** v článcích s plynulým přesunem indikátoru
   (pokud už je, zvýraznit i progress čtení — tenká linka nahoře).
5. **Choropleth mapa**: postupné obarvení krajů (stagger dle pořadí
   v žebříčku) při změně indikátoru — propojí mapu s tabulkou.
6. **View Transitions API** pro přechody mezi stránkami (progressive
   enhancement, 2 řádky CSS) — jemný crossfade sedí k papírové estetice
   a sjednotí multi-page navigaci.
7. **Hover mikrointerakce karet** — lehký lift (translateY(-2px) + stín)
   pro klikatelné karty, ať je afordance „tohle je odkaz" zřetelná; dnes
   karty vypadají staticky a klikatelnost prozrazuje jen „Detail →".

Anti-doporučení: žádné parallaxy, žádné nekonečné loop animace mimo ticker —
současná zdrženlivost je hodnota.

## D. Grafika a vizuál

11. **Dark mode reálně neexistuje.** `styles.css` neobsahuje jediný
    `prefers-color-scheme` blok (CLAUDE.md dark mode zmiňuje — dokumentace
    předbíhá realitu). Buď doplnit (CSS custom properties už jsou všude,
    takže jde hlavně o přemapování ~15 proměnných + obrázky), nebo z
    dokumentace odstranit. Pro datový web čtený večer má dark mode smysl;
    papírová estetika se dá převést na „noční inkoust" (tmavě modrošedý
    papír, ne čistá čerň).
12. **Mapa ČR a donut bez echarts** — choropleth 14 krajů je ideální
    kandidát na inline SVG generované build-time z `cz-regions.geojson`
    (jednorázový skript), donut je 20 řádků SVG. Odpadne největší externí
    závislost (§1), mapa bude stylovatelná CSS proměnnými a funkční offline.
13. **Sparkliny v kartách** (viz §7) — největší grafická příležitost:
    trend data už existují, karty mají prázdné místo, a „směr vývoje" je
    přesně to, co HSPA Kompas slibuje.
14. **Vizualizace dimenzí na homepage** — skóre 30/21/26/42/44/80 se ukazuje
    číslem + mini progress barem; zvážit kompasovou/radiální mikrografiku
    (šest paprsků) jako brand-konzistentní alternativu progress baru.

## E. Výkon

15. **`styles.css` 378 KB nenminifikovaný na každé stránce** (Vercel bez
    build kroku → soubor jde ven, jak je; gzip pomůže, ale parse cost
    zůstává). Doporučení: minifikace v CI (esbuild/lightningcss, 1 krok
    v GitHub Actions před deployem) → ~60 % úspora; dlouhodobě split na
    core + per-page vrstvy.
16. **Homepage stahuje ~713 KB JSON** (indicators 153 KB, articles 246 KB,
    strategies, explainers, regions…). `articles.json` se fetchuje ve 3
    místech `app.js` (cache to zachrání, ale jeden modul-level promise je
    čistší). Doporučení: `indicators-summary.json` bez trend polí pro grid
    (trend až na detailu / pro sparkline jen posledních 5 bodů),
    `articles-index.json` jen s metadaty pro homepage (bez plných perexů
    všech 113 článků).
17. **139 karet = 4 300 DOM nodes při loadu** — progressive disclosure (§6)
    to řeší zároveň s UX.

## F. Přístupnost (axe-core + manuální)

Skóre je nadprůměrné; zbývá:

18. **`<h6>O projektu</h6>` v patičce** přeskakuje úrovně (h3 → h6 na
    všech stránkách) — vizuální styl patičkových nadpisů udělat třídou,
    element snížit na h3/h4 nebo `<p class="footer-h">`.
19. **`.masthead-strip` (datum) je mimo landmark** — obalit do `<header>`
    nebo přidat `role="complementary"`/přesunout do existujícího headeru.
20. Ověřit **focus trap a návrat fokusu** u search overlaye a mobilního
    menu (otevřít → Tab nesmí utéct pod overlay, Esc vrací fokus na
    spouštěč). Netestováno do hloubky — doporučuji ruční průchod.
21. Newsletter popup: po otevření nekrade fokus (dobře), ale ujistit se,
    že je v DOM pořadí až za obsahem, ať screen reader čtenáře nepřeruší.

## G. Mobil

Základ je zdravý: hamburger s ARIA, žádný horizontální overflow, fold
homepage funguje. Doporučení:

22. **Dlouhé články (10 000+ px)**: na mobilu chybí orientace — sticky
    tenký progress bar + sbalitelný „Obsah článku" (accordion pod hlavičkou)
    by výrazně pomohly.
23. **Grid indikátorů na mobilu** = 139 karet pod sebou ≈ nekonečný scroll;
    progressive disclosure z §6 je na mobilu ještě důležitější.
24. Tabulky v článcích otestovat na 320–390 px (overflow-x wrapper se
    stínovým hintem „dá se scrollovat").
